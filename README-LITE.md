# RepoForge Lite

**A safe, standalone Python project bootstrapper in one standard-library file.**

RepoForge Lite creates a named project directory, isolated environment,
installable package foundation, resolved dependency lock, behavior test, and
scoped initial Git commit. Existing files are preserved by default.

```bash
python repoforge_lite.py my-project --owner YOUR_GITHUB_NAME
```

That command creates `./my-project` and records
`https://github.com/YOUR_GITHUB_NAME/my-project.git` as `origin`. Lite does not
create the remote repository or push to it.

RepoForge Lite has no third-party runtime dependencies. It supports Python 3.10
and newer on Windows, macOS, and Linux; use a currently supported Python patch
release for production work.

## Local quickstart

Create a local-only project:

```bash
python repoforge_lite.py --directory my-project
```

The completed project contains:

- `.venv/` with upgraded pip and installed project dependencies.
- `requirements.txt` for Requests, python-dotenv, and Rich.
- `requirements-dev.txt` for runtime inputs plus pytest.
- `requirements.lock`, resolved from the installed environment and reused on
  later runs.
- Installable PEP 621 metadata in `pyproject.toml`.
- A runnable `main.py` and behavior test in `tests/test_smoke.py`.
- A practical `.gitignore` and generated project README.
- A `main` branch with a commit containing only files generated by Lite.

Activate and verify the result:

```bash
cd my-project

# Windows
.venv\Scripts\activate
# macOS / Linux
source .venv/bin/activate

pytest
python main.py
```

## Reruns and safety

- Every write is confined to the resolved target directory.
- Existing files remain untouched unless `--force` is explicit.
- A normal rerun installs from the existing lock and preserves it byte for
  byte.
- Git stages and commits only paths generated in the current run. Existing
  staged, modified, and untracked user files remain outside the Lite commit.
- `--dry-run` prints the complete plan without creating directories, writing
  files, or running subprocesses.
- `--no-commit` initializes Git and leaves all generated files unstaged.
- An existing `origin` is preserved.
- Invalid targets and missing Git identity fail before project files are
  written. Use `--no-commit` when another workflow owns the first commit.

Useful controls:

```bash
python repoforge_lite.py --help
python repoforge_lite.py --directory my-project --dry-run
python repoforge_lite.py --directory my-project --skip-install
python repoforge_lite.py --directory my-project --skip-venv --no-commit
python repoforge_lite.py --directory my-project --force
```

`--force` intentionally replaces generated-path files and resolves a fresh lock.
Review local changes before using it in an existing repository.

## Verify the source and release

The WPAI source repository pins its QA tools and tests Lite with warnings as
errors, real Git repositories, an actual generated virtual environment, lock
reuse, runnable behavior, and deterministic release integrity.

```bash
python -m pip install -r requirements-dev.txt
ruff check repoforge_lite.py tests/test_repoforge_lite.py
mypy repoforge_lite.py
python -W error -m pytest tests/test_repoforge_lite.py -q

python build_release.py --edition lite
python build_release.py --edition lite --check
```

The versioned Lite ZIP contains only `repoforge_lite.py`, this README, the MIT
license, and `MANIFEST.json`. The manifest records the SHA-256 digest and byte
length of every shipped file; the builder also enforces fixed member order,
timestamps, permissions, compression, and safe paths.
